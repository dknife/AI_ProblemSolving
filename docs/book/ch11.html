CHAPTER 11

파이썬 앱으로 반복을 없앤다

이 장을 마치면
  • 파이썬이 잘하는 일과 웹이 잘하는 일을 구분할 수 있다.
  • 설치 없이 브라우저에서 파이썬 코드를 실행할 수 있다.
  • 자료를 읽어 정리하고 결과 파일로 내보낼 수 있다.
  • 결과를 그림으로 확인할 수 있다.
  • 화면이 있는 간단한 앱으로 만들어 남에게 줄 수 있다.

웹 페이지로는 다루기 번거로운 일들이 있다. 파일 수십 개를 한꺼번에 처리하거나, 표 몇천 줄을 정리하거나, 매주 같은 계산을 반복하는 일이 그렇다. 이런 일에는 파이썬이 맞는다.

이 장에서도 문법을 배우지 않는다. 대신 어떤 일을 파이썬에게 맡길 수 있는지 알아보는 눈과, 에이전트에게 그 일을 정확히 시키는 방법을 익힌다. 설치는 하지 않는다 — 브라우저에서 실행되는 무료 환경을 쓴다.

11.1 파이썬이 잘하는 일

9–10장에서 만든 것은 남이 열어 쓰는 화면이었다. 이 장에서는 다른 종류를 만든다. 내 반복 작업을 대신 해 주는 것이다.

웹으로는 번거로운 일들

다음 같은 일은 브라우저 안에서 하기 어렵거나 번거롭다.

  • 폴더에 있는 파일 백 개의 이름을 규칙대로 바꾼다
  • 표 파일 여러 개를 하나로 합친다
  • 수천 줄짜리 자료에서 조건에 맞는 것만 뽑는다
  • 같은 보고서를 매주 자동으로 만든다
  • 사진 이백 장의 크기를 한 번에 맞춘다

공통점이 보인다. 양이 많고, 파일을 직접 다루고, 사람이 화면을 볼 필요가 없다. 이런 일에 파이썬이 맞는다.

판단 기준

1.4절과 8.1절에서 본 기준을 마지막으로 확정한다.

결과를 그림으로 봐야 한다파이썬도구가 잘 갖춰져 있다

이 장에서 만들 것

책의 예시를 이어 간다. 9–10장에서 만든 웹 도구로 동아리원들이 지출을 입력하고, 각자 CSV 파일을 내보내 총무에게 보냈다. 이제 총무에게는 여러 개의 CSV 파일이 있다.

총무가 할 일은 이렇다.

  1. 여러 파일을 하나로 합친다
  2. 중복된 것을 찾아낸다 (같은 지출을 두 사람이 올린 경우)
  3. 항목별·사람별로 집계한다
  4. 통장 거래 내역과 대조해 빠진 것을 찾는다
  5. 월간 보고서 파일을 만든다

이 다섯 가지를 손으로 하면 한 시간이 넘는다. 파이썬으로는 몇 초다. 9장의 웹과 11장의 파이썬이 짝을 이뤄 원래 문제를 끝까지 해결하는 구조다.

요점

웹과 파이썬은 경쟁하는 선택지가 아니라 같은 문제의 다른 구간을 맡는 짝이 될 수 있다. 사람이 입력하는 곳은 웹, 많은 양을 처리하는 곳은 파이썬.

여러분의 경우

자기 문제가 웹만으로 끝났다면, 이 장에서는 그 결과물이 만들어 내는 자료를 다루는 것을 만들면 된다. 예를 들면 이런 것들이다.

여기서도 문법은 배우지 않는다

이 장에서 파이썬 코드가 나오지만, 그것을 쓰는 법을 배우지는 않는다. 목표는 둘이다.

첫째, 무엇을 맡길 수 있는지 아는 눈. 어떤 일이 파이썬으로 몇 초에 되는 일인지 감이 생기면, 앞으로 반복 작업을 만날 때마다 이건 맡길 수 있겠다는 판단이 선다.

둘째, 시키고 확인하는 법. 자료 처리는 조용히 틀린다. 오류 없이 잘 돌았는데 결과가 잘못된 경우가 많다. 그것을 잡아내는 법이 이 장의 절반이다.

주의

자료 처리에서 가장 위험한 것은 잘 돌았다고 믿는 것이다. 212건을 처리했는데 결과가 198건이면 14건이 어디론가 사라진 것인데, 아무도 알려 주지 않는다. 7.4절에서 말한 건수 확인이 이 장 내내 반복된다.

11.2 코랩에서 첫 코드 돌리기

파이썬을 설치하지 않는다. 브라우저에서 실행되는 무료 환경을 쓴다.

노트북이라는 형태

브라우저에서 파이썬을 실행하는 노트북무료
colab.research.google.com

계정만 있으면 설치 없이 파이썬을 실행할 수 있다. 코드와 결과와 설명이 한 화면에 함께 남는 노트북notebook 형태이며, 파일을 올리고 내려받을 수 있다. 만든 것을 링크로 공유할 수도 있다. 무료 범위에서 이 수업의 모든 실습이 가능하다.

노트북은 칸(셀)으로 이루어진다. 각 칸에 코드를 넣고 실행하면 그 아래에 결과가 나온다. 위에서부터 차례로 실행하는 것이 기본이다.

이 형태가 초심자에게 좋은 이유가 있다. 한 번에 조금씩 실행하고 결과를 바로 볼 수 있기 때문이다. 전체를 다 짜고 한꺼번에 돌리는 것보다 훨씬 덜 막힌다.

첫 실행

새 노트북을 만들고 첫 칸에 다음을 넣어 실행한다.

print("안녕하세요")
2 + 3
안녕하세요
5

이것이 되면 준비 끝이다. 파이썬이 여러분 컴퓨터가 아니라 인터넷 어딘가의 컴퓨터에서 돌고 있고, 결과만 브라우저로 돌아온 것이다.

파일 올리고 내려받기

여기서 가장 많이 막힌다. 미리 확실히 해 두자.

파이썬이 도는 컴퓨터는 내 컴퓨터가 아니다. 그래서 내 파일을 쓰려면 올려야 하고, 결과를 가지려면 내려받아야 한다.

from google.colab import files
uploaded = files.upload()      # 파일 고르기 창이 뜬다
print(uploaded.keys())         # 올라온 파일 이름 확인
코드 11.1: 파일 올리기 — 코랩의 경우
files.download('결과.csv')      # 내 컴퓨터로 받는다
코드 11.2: 파일 내려받기
주의

노트북을 닫거나 한동안 두면 올렸던 파일이 사라진다. 다음에 열면 다시 올려야 한다. 결과 파일은 만든 즉시 내려받는 습관을 들이자. 한 시간 작업한 결과를 날리는 일이 실제로 자주 생긴다.

코드를 직접 쓰지 않는다

이 장에서 나오는 코드는 여러분이 타이핑할 것이 아니다. 인공지능에게 받아 붙여 넣고 실행한다. 요청 방식은 지금까지와 같다.

프롬프트ColabChatGPTClaudeGemini
코랩에서 실행할 파이썬 코드를 만들어 줘.
[자료] 지출_2026-03.csv 파일. 열은 날짜, 항목, 금액, 결제수단, 이름. 각 행이 지출 한 건. 첫 줄은 열 이름. 약 60행.
[할 일] 항목별 합계를 구해 금액이 큰 순서로 출력해 줘.
[형식] 코드는 한 칸에 다 들어가게 한 덩어리로 주고, 각 줄이 무엇을 하는지 짧은 주석을 달아 줘.
[확인] 처리한 행이 몇 개인지, 금액이 비어 있거나 숫자가 아닌 행이 몇 개인지도 함께 출력해 줘.
[제약] 설치가 필요한 것은 쓰지 말고, 코랩에 기본으로 있는 것만 써 줘.
프롬프트 11.3: 파이썬 코드 요청의 기본형

마지막 두 요소가 중요하다. 확인 항목이 없으면 결과 숫자만 나오고 그것이 맞는지 알 수 없다. 제약이 없으면 설치가 필요한 도구를 쓰라고 할 수 있다.

돌려 보고 나오는 것

import pandas as pd

df = pd.read_csv('지출_2026-03.csv')     # 파일을 읽는다
print("읽은 행 수:", len(df))            # 몇 건인지 확인

# 금액이 숫자가 아닌 행 확인
bad = df[pd.to_numeric(df['금액'], errors='coerce').isna()]
print("금액이 이상한 행:", len(bad))

df['금액'] = pd.to_numeric(df['금액'], errors='coerce')  # 숫자로 바꾼다
result = df.groupby('항목')['금액'].sum()  # 항목별로 더한다
print(result.sort_values(ascending=False)) # 큰 것부터 출력
코드 11.4: 돌아온 코드 — 항목별 합계
읽은 행 수: 62
금액이 이상한 행: 1
항목
대관료    500000
간식      320000
인쇄비    127000
교통비     48000
물품       32000

금액이 이상한 행: 1이 이 출력에서 가장 중요한 줄이다. 한 건이 계산에서 빠졌다는 뜻이고, 그 한 건을 확인해야 한다. 이 줄이 없었다면 합계가 조용히 틀린 채로 넘어갔을 것이다.

요점

자료 처리 코드에는 언제나 확인 출력을 함께 요청한다. 몇 건을 읽었는지, 몇 건이 이상한지, 몇 건이 결과에 들어갔는지. 이 세 숫자가 맞아야 결과를 믿을 수 있다.

한 칸씩 나눠 실행하기

긴 코드를 한 번에 돌리지 말고 나눠 실행하는 것이 좋다.

  1. 파일을 읽는다 → 몇 행인지 확인
  2. 자료를 살펴본다 → 처음 다섯 줄을 출력해 본다
  3. 정리한다 → 무엇이 바뀌었는지 확인
  4. 계산한다 → 결과 확인
  5. 내보낸다 → 파일 확인

각 단계에서 결과를 보면 어디서 틀어졌는지 바로 알 수 있다. 이것이 노트북 형태의 가장 큰 장점이다.

df.head()        # 처음 다섯 줄만 보여 준다
df.info()        # 각 열이 어떤 종류인지
df['항목'].unique()   # 항목에 어떤 값들이 있는지

세 번째 줄이 특히 유용하다. 5.4절에서 걱정한 표기 불일치가 여기서 드러난다 — 간식과 간식비가 따로 나오면 통일해야 한다는 뜻이다.

11.3 자료를 읽고 정리하고 내보내기

이 절이 11장의 중심이다. 여러 파일을 하나로 합치고, 지저분한 것을 정리하고, 결과를 내보내는 흐름 하나를 끝까지 완성한다.

실제 자료는 언제나 지저분하다

교과서의 자료는 깨끗하지만 실제 자료는 그렇지 않다. 5.4절에서 예고한 것들이 여기서 전부 나타난다.

오른쪽 칸을 사람이 정해야 한다. 인공지능에게 알아서 정리해 줘라고 하면 알아서 정하는데, 그 판단이 우리 의도와 다를 수 있다. 예를 들어 이름이 빈 행을 조용히 버릴 수도 있다.

실습 11-1. 첫 실행과 파일 다루기

노트북 환경에 들어가 다음을 확인한다.

  • 새 노트북을 만들고 print("안녕하세요")가 실행된다
  • 내 컴퓨터의 파일을 올릴 수 있다
  • 올린 파일의 처음 다섯 줄을 볼 수 있다
  • 파일을 만들어 내려받을 수 있다

마지막 두 개가 이 장 내내 쓰인다. 여기서 막히면 다음으로 넘어갈 수 없다.

실습 11-4. 정리하고 확인하기

방침대로 처리한다. 그리고 확인한다.

  • 원본 파일을 고치지 않았다
  • 버린 행이 따로 저장되었다
  • 각 단계의 건수가 출력되었다
  • 예상한 최종 행 수와 실제가 같다
  • 다르다면 그 이유를 찾았다

4번이 다르면 반드시 원인을 찾는다. 대충 맞으니 넘어가자가 이 장에서 가장 위험한 태도다.

실습 11-5. 반복을 실제로 없애기

지금까지 손으로 하던 작업 하나를 통째로 자동화한다. 그리고 4.4절의 성공 기준으로 잰다.

맨 아래 칸이 재미있는 질문이다. 코드를 만드는 데 두 시간이 들었고 매번 세 시간을 아낀다면 첫 번째부터 이익이다. 반대로 한 번만 할 일이었다면 손해다. 이 계산을 해 보는 것이 실습의 목적이다.

실습 11-6. 그림 한 장

정리한 자료로 그림을 그리고, 그것이 무엇을 보여 주는지 두 문장으로 쓴다.

  1. 첫 문장: 그림에서 읽히는 것 (자료만으로 말할 수 있는 것)
  2. 둘째 문장: 왜 그런지에 대한 해석 (자료 밖의 지식이 필요한 것)
  3. 둘을 구분해 표시한다

그리고 11.4절의 네 가지 함정(축 자르기, 기간 자르기, 비교 대상 없음, 작은 수를 비율로)에 걸리지 않았는지 확인한다.

실습 11-7. 화면 붙이기 (선택)

11.5절의 프롬프트로 화면을 붙인다. 시간이 부족하면 여기까지 오지 않아도 된다 — 실습 11-5까지가 이 장의 필수다.

붙였다면 다음을 확인한다.

  • 파일을 올리지 않았을 때 오류 없이 안내가 나온다
  • 정리 방침이 화면에 표시된다
  • 결과를 내려받을 수 있다
  • 남 한 명이 설명 없이 써 봤다

실습 11-8. 두 결과물 이어 보기

9–10장의 웹과 11장의 파이썬을 실제로 이어서 한 바퀴 돌려 본다.

  1. 웹에서 자료를 입력한다 (최소 10건)
  2. [표로 내보내기]로 파일을 만든다
  3. 그 파일을 노트북에 올려 정리한다
  4. 집계 결과를 만든다
  5. 처음 입력한 10건과 최종 집계가 맞는지 확인한다

5번에서 어긋나면 어디서 어긋났는지 찾는다. 대개 형식 문제이며, 그것을 찾는 과정이 12장의 예습이 된다.

11장 요약
  • 파이썬이 맞는 일은 양이 많고, 파일을 직접 다루고, 사람이 화면을 볼 필요가 없는 일이다. 웹은 사람이 입력하고 결과를 보는 자리를 맡는다.
  • 웹과 파이썬은 경쟁하는 선택지가 아니라 같은 문제의 다른 구간을 맡는 짝이 될 수 있다. 입력은 웹으로, 대량 처리는 파이썬으로.
  • 설치하지 않는다. 노트북notebook 환경에서 브라우저로 실행한다. 칸 단위로 조금씩 실행하고 결과를 바로 보는 형태가 초심자에게 유리하다.
  • 노트북이 도는 컴퓨터는 내 컴퓨터가 아니다. 파일은 올려야 쓸 수 있고 결과는 내려받아야 가질 수 있으며, 한동안 두면 사라진다. 만든 즉시 내려받는다.
  • 코드는 직접 쓰지 않고 받아서 실행한다. 요청에는 언제나 확인 출력(몇 건을 읽었나, 몇 건이 이상한가, 몇 건이 결과에 들어갔나)을 함께 요구한다.
  • 실제 자료는 언제나 지저분하다 — 표기 불일치, 빈칸, 형식 불일치, 숫자 아닌 숫자, 중복, 이상값. 각각을 어떻게 처리할지는 사람이 정한다.
  • 정리하기 전에 먼저 살펴본다. 아직 고치지 말라고 못 박고 무엇이 있는지 본 뒤 방침을 정한다.
  • 정리 방침에는 처리 후 몇 건이 남을지 예상을 적어 둔다. 실제 결과와 대조해 확인하기 위해서다.
  • 원본은 고치지 않는다. 정리는 새 파일로 하고, 버리는 행은 버리기 전에 따로 저장한다. 방침이 틀렸어도 처음부터 다시 할 수 있다.
  • 중복은 자동으로 지우지 않는다. 진짜 중복인지 같은 날 같은 금액의 다른 건인지는 사람이 판단한다.
  • 그림은 막대·선·분포 셋이면 충분하다. 원그래프는 권하지 않는다.
  • 그림으로 잘못 말하는 네 가지 — 세로축을 0에서 시작하지 않기, 기간을 골라 자르기, 비교 대상 없이 보여 주기, 작은 수를 비율로 말하기. 이것은 정직성 이전에 자기가 속지 않기 위한 문제다.
  • 그림을 그렸으면 자료에서 읽히는 것과 자료 밖의 지식이 필요한 해석을 구분해 두 문장으로 적는다.
  • 파이썬 코드에 화면을 붙이면 남이 쓸 수 있게 된다. 다만 무료 환경은 잠들고, 용량이 제한되고, 자료가 남지 않는다. 남의 자료를 서버에 남기지 않게 만든다.
  • 자동으로 돌게 하기 전에 손으로 여러 번 돌려 결과를 확인해 본 것이어야 한다. 자동화된 것은 아무도 결과를 보지 않게 되기 쉽다.
11장 연습문제
  1. ★ 다음 작업에 웹과 파이썬 중 어느 쪽이 맞는지 고르고 이유를 쓰시오(표 11.1 참조).
    1. 학과 행사 참가 신청을 받는다
    2. 3년 치 실험 기록 파일 36개를 하나로 합친다
    3. 조원들이 각자 진행 상황을 표시한다
    4. 사진 200장의 파일 이름을 촬영일 순으로 바꾼다
  2. ★ 자료 처리 코드를 요청할 때 반드시 함께 요구해야 할 확인 출력 세 가지를 쓰고, 각각이 무엇을 막아 주는지 설명하시오.
  3. ★ 실제 자료에서 흔히 만나는 문제 여섯 가지(표 11.3)를 쓰고, 자기 자료에서 실제로 발견한 것에 표시하시오.
  4. ★★ 다음 지시의 문제점을 지적하고 11.3절의 방식으로 고쳐 쓰시오.

    이 파일 좀 깔끔하게 정리해 줘.

  5. ★★ 어떤 학생이 212건의 설문 자료를 정리했더니 결과가 198건이 되었다. 이 상황에서 확인해야 할 것을 순서대로 쓰고, 이런 일을 미리 막으려면 요청을 어떻게 했어야 하는지 설명하시오.
  6. ★★ 다음 그림 설명에서 11.4절의 네 가지 함정 중 어떤 것에 해당하는지 찾고, 어떻게 고쳐야 하는지 쓰시오.
    1. 설문 결과 응답자의 75%가 찬성했습니다 (응답자 4명)
    2. 최근 3개월간 지출이 급증했습니다 (세로축이 90만 원부터 시작)
    3. 올해 참여율이 크게 올랐습니다 (5년 중 최근 2년만 표시)
  7. ★★★ 자기 자료를 대상으로 11.3절의 전체 흐름(살펴보기 → 방침 정하기 → 정리 → 확인 → 내보내기)을 수행하고 보고하시오. 보고에는 (1) 살펴본 결과, (2) 정리 방침 표와 예상 행 수, (3) 실제 처리 기록, (4) 예상과 실제가 달랐다면 그 원인, (5) 제외된 행의 내용과 제외가 타당했는지에 대한 판단이 포함되어야 한다.
  8. ★★★ 손으로 하던 작업 하나를 자동화하고, 다음을 계산해 보고하시오. (1) 손으로 할 때의 실측 시간, (2) 코드를 만드는 데 든 시간, (3) 실행과 결과 확인에 드는 시간, (4) 몇 번 반복하면 본전인지, (5) 그럼에도 자동화하지 않는 편이 나았을 조건은 무엇일지.
