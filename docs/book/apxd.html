APPENDIX D

배포와 공유 안내

10장에서 왜 배포하는지를 다루었다면, 이 부록은 어떻게 하는지를 순서대로 안내한다. 서비스 화면은 자주 바뀌므로 버튼 이름보다 하는 일의 순서를 기억하자. 이름이 달라져도 순서는 같다.

계정과 저장소 준비

계정 만들기

  1. 서비스에 가입한다 (github.com 등)
  2. 개인 이메일로 가입한다 — 학교 계정은 졸업하면 닫힌다
  3. 사용자 이름을 정한다. 이것이 나중에 주소에 들어간다
  4. 이메일 인증을 마친다
주의

사용자 이름은 나중에 바꾸기 번거롭고, 바꾸면 공개 주소도 바뀐다. 포트폴리오로 쓸 생각이라면 남에게 보여도 괜찮은 이름으로 정하자.

저장소 만들기

  1. [새 저장소] 또는 [New repository]를 누른다
  2. 이름을 정한다 — 영문 소문자와 하이픈만 쓴다 (club-expense)
  3. 공개(Public)로 만든다 — 비공개면 웹으로 보이지 않는다
  4. 만들기를 누른다

이름이 주소에 들어간다. https://<사용자이름>.github.io/<저장소이름>/ 형태가 된다.

정적 페이지 배포하기

9장에서 만든 .html 파일 하나를 올린다.

파일 올리기

  1. 파일 이름을 index.html로 바꾼다 (주소가 짧아진다)
  2. 저장소 화면에서 [파일 추가] → [파일 업로드]
  3. 파일을 끌어다 놓는다
  4. 아래 [변경 사항 커밋]을 누른다 (설명은 안 적어도 된다)

명령줄은 필요 없다. 파일이 하나뿐이므로 웹 화면에서 끌어다 놓는 것으로 충분하다.

공개 설정 켜기

  1. 저장소의 [설정(Settings)]으로 간다
  2. 왼쪽 메뉴에서 [Pages]를 찾는다
  3. 원본(Source)을 main 브랜치, 폴더는 / (root)로 지정
  4. 저장한다
  5. 잠시 뒤 그 화면에 주소가 표시된다

주소 확인

반영에 몇 분이 걸린다. 바로 안 열려도 정상이다. 5분쯤 뒤 다시 열어 본다.

내 결과물 주소
사용자 이름   :
저장소 이름   :
공개 주소     : https://          .github.io/          /
만든 날짜     :
공개 범위     : 전체 / 링크 아는 사람만
유지 계획     : 학기 후에도 유지 / 학기 말에 내림

고친 것을 다시 올리기

  1. 내 컴퓨터의 파일을 고친다
  2. 내 컴퓨터에서 열어 확인한다 (이 단계를 건너뛰지 않는다)
  3. 사본을 남긴다
  4. 저장소에서 같은 방식으로 업로드한다 (덮어쓰기됨)
  5. 몇 분 뒤 강제 새로고침(Ctrl+Shift+R)으로 확인한다

노트북과 앱 공유하기

11장의 파이썬 결과물을 공유하는 방법이다.

노트북 자체를 공유하기

가장 간단하다. 노트북 화면에서 [공유] → [링크가 있는 모든 사용자]로 바꾸고 링크를 복사한다.

  • 장점 — 준비가 필요 없다. 코드와 결과가 함께 보인다
  • 한계 — 보는 사람도 계정이 필요할 수 있고, 실행하려면 사용법을 알아야 한다

수업 제출이나 조원 공유에는 이것으로 충분하다.

앱으로 만들어 주소 붙이기

11.5절에서 화면을 붙인 경우다. 대체로 이 순서를 따른다.

  1. 코드를 저장소에 올린다 (앱 파일 + 필요한 목록 파일)
  2. 앱 호스팅 서비스에 가입하고 저장소를 연결한다
  3. 실행할 파일을 지정한다
  4. 배포를 누르고 기다린다 (처음에는 몇 분 걸린다)
  5. 주소를 확인한다
주의

무료 계정의 한계를 알아 두자. 한동안 아무도 안 쓰면 잠들어 다음 사람이 열 때 30초쯤 걸린다. 발표 직전에는 미리 한 번 열어 깨워 두자.

자료 파일을 함께 올릴 때

올려도 되는지 판단하기

표 D.1: 이 자료를 공개 저장소에 올려도 되는가
자료 올려도? 대안
내가 만든 예시 자료예 —
공개된 통계·자료예출처 표시
동아리 지출 내역조건부이름을 지우고

올려도 되는 형태로 바꾸기

  • 익명화 — 이름을 학생1, A 등으로 바꾼다
  • 표본만 — 전체 대신 열 줄 정도만 (형식을 보여 주는 용도)
  • 합성 자료 — 실제와 형식만 같은 가짜 자료를 만든다
  • 집계만 — 원본 대신 결과 표만 올린다

세 번째가 가장 안전하다. 형식이 같은 예시 자료 20건을 만들어 줘라고 하면 몇 초에 만들어진다.

주의

공개 저장소에 한 번 올린 것은 지워도 기록이 남을 수 있다. 올리기 전에 확인하는 것이 유일한 방법이다.

공개 전 점검 목록

배포하기 전에 반드시 한 번 돌린다. 10.4절과 12.5절의 목록을 합친 것이다.

  • 개인정보 — 실제 사람의 이름·학번·연락처가 파일 안에 없는가
  • 시험 자료 — 시험용으로 넣어 둔 실제 자료가 남아 있지 않은가
  • 주석 — 코드에 남긴 메모(일단 대충 함, 계정 정보 등)가 없는가
  • 출처 — 가져다 쓴 이미지·글꼴·코드의 조건을 확인했는가
  • 안내 — 무엇이 저장되고 누가 보는지 화면에 밝혔는가
  • 지우기 — 사용자가 자기 자료를 지울 수 있는가
  • 연락처 — 문제가 생겼을 때 알릴 방법이 있는가
  • 정체 — 이것이 수업 과제물임을 밝혔는가
  • 유지 — 언제까지 유지할지 정하고 알렸는가
  • 동작 — 12.3절의 확인 목록을 통과했는가

포트폴리오 페이지 만들기

13.5절의 기록을 공개 페이지 하나로 묶는다.

어디에 두는가

두 가지 방법이 있다.

  • 같은 저장소에 — portfolio.html로 함께 올린다. 주소는 .../portfolio.html
  • 별도 저장소에 — 여러 프로젝트를 모을 계획이면 이쪽. 이 경우 저장소 이름을 <사용자이름>.github.io로 만들면 주소가 가장 짧아진다

구성

13.5절의 서식을 따른다. 요약하면 이렇다.

포트폴리오 페이지
제목 + 한 문장 요약 (숫자 포함)
1. 문제        - 무엇이 문제였고 어떻게 확인했는가
2. 과정        - 처음 스케치 -> 완성 화면, 검토한 대안
3. 결과        - 주소(링크), 화면 캡처, 성공 기준 대비, 사용자 반응
4. 배운 것     - 안 된 것과 원인, 다시 한다면
5. 만드는 데 쓴 것 - AI 사용 기록

마지막 확인

  • 주소가 다른 기기(휴대전화)에서 열린다
  • 결과물 링크가 눌러서 열린다
  • 화면 캡처를 남겨 두었다 (주소가 죽어도 보여 줄 수 있게)
  • 파일 전체를 내 컴퓨터에도 백업했다
  • 계정이 개인 이메일로 되어 있다
요점

이 부록의 절차는 바뀐다. 그러나 순서는 바뀌지 않는다 — 계정을 만들고, 자리를 만들고, 파일을 올리고, 공개를 켜고, 주소를 확인한다. 화면이 낯설어 보이면 이 다섯 단계 중 지금 어디인지부터 찾자.
