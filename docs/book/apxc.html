APPENDIX C

자주 만나는 오류와 해결

12장에서 오류를 읽고 전달하는 법을 다루었다. 이 부록은 초심자가 반복해서 만나는 상황을 유형별로 모은 것이다. 각 항목은 어떻게 보이는가 — 왜 생기는가 — 무엇을 하면 되는가 순으로 정리했다.

막혔을 때 여기부터 보자. 여기 있는 것들은 프로그래밍 실력과 무관하며, 대부분 1–2분이면 해결된다.

화면에 아무것도 안 뜬다

가장 흔하고 가장 겁먹는 상황이다. 순서대로 확인한다.

표 C.1: 빈 화면 — 확인 순서
확인 어떻게
1저장했는가편집기에서 저장(Ctrl+S)
2새로고침했는가Ctrl+Shift+R (강제 새로고침)
3맞는 파일인가브라우저 주소창의 경로 확인
4확장자가 맞는가.html.txt가 아닌지
5콘솔에 뭐가 있나F12 → 콘솔 탭

콘솔 여는 법

브라우저에서 F12(맥은 Cmd+Option+I)를 누른다. 여러 탭 중 콘솔을 고른다. 붉은 글씨가 있으면 그것이 원인이다.

그 글씨를 요약하지 말고 그대로 복사해서 12.2절의 형식으로 물어본다.

콘솔에도 아무것도 없다면

파일이 아예 안 읽히고 있을 가능성이 높다. 경로나 확장자 문제다. 파일을 마우스로 브라우저 창에 끌어다 놓아 보면 바로 알 수 있다.

오류 메시지가 뜬다

이름을 못 찾을 때

Uncaught ReferenceError: totalAmount is not defined
Uncaught TypeError: Cannot read properties of null (reading 'value')
NameError: name 'df' is not defined

왜: 이름을 잘못 적었거나, 이름을 바꾸면서 한 곳만 바꿨거나, 아직 만들어지지 않은 것을 쓰려 했다. 파이썬에서는 위 칸을 실행하지 않고 아래 칸을 실행한 경우가 많다.

할 일: 메시지에 나온 이름을 파일에서 찾아본다(Ctrl+F). 몇 군데 나오는가? 철자가 모두 같은가? 대소문자까지 같은가?

파일을 못 찾을 때

FileNotFoundError: [Errno 2] No such file or directory: 'expense.csv'
Failed to load resource: the server responded with a status of 404

왜: 파일을 안 올렸거나, 이름이 다르거나, 다른 폴더에 있다. 노트북 환경에서는 세션이 끊겨 올린 파일이 사라진 경우가 많다(11.2절).

할 일: 파일 이름을 복사해서 붙여 넣는다 — 손으로 치면 틀린다. 한글 파일 이름은 특히 그렇다. 노트북이라면 파일을 다시 올린다.

형식이 안 맞을 때

ValueError: could not convert string to float: '12,000원'
TypeError: unsupported operand type(s) for +: 'int' and 'str'

왜: 숫자 자리에 글자가 들어 있다. 쉼표, 단위, 공백, 빈칸이 흔한 원인이다(11.3절).

할 일: 메시지에 나온 값('12,000원')을 자료에서 찾아 확인한다. 그 값을 어떻게 처리할지 정한 뒤(고칠지 버릴지) 다시 요청한다.

괄호나 따옴표가 안 맞을 때

Uncaught SyntaxError: Unexpected end of input
SyntaxError: unexpected EOF while parsing

왜: 코드를 손으로 고치다가 괄호나 따옴표 짝이 깨졌다.

할 일: 사본으로 되돌린다(8.5절). 그게 가장 빠르다. 되돌릴 사본이 없다면 파일 전체를 주고 괄호나 따옴표 짝이 맞지 않는 곳을 찾아 달라고 한다.

어제 되던 것이 오늘 안 된다

표 C.2: 어제는 됐는데
원인 확인
다른 파일을 열고 있다브라우저 주소창의 경로
어제 고친 것을 저장 안 했다파일 수정 시각
브라우저가 옛 화면을 보여 준다강제 새로고침
저장된 자료가 깨졌다[전체 지우기] 후 다시
무료 한도가 떨어졌다서비스 화면의 안내
서비스가 바뀌었다공지 확인
요점

이 절의 대부분은 사본을 남기는 습관으로 해결된다. 잘 되는 상태가 나올 때마다 v1, v2로 저장해 두면, 되돌아갈 곳이 있어 이런 상황이 사고가 되지 않는다.

자료를 넣으면 깨진다

한글이 깨진다

왜: 파일의 저장 방식(인코딩)이 다르다. 엑셀에서 만든 CSV는 특히 자주 그렇다.

할 일: 엑셀에서 열었을 때 한글이 깨지지 않게 저장해 줘라고 요청한다. 읽을 때 문제라면 이 파일의 인코딩을 확인해서 맞게 읽어 줘라고 한다.

열이 안 나뉜다

한 칸에 모든 값이 들어가 보인다.

왜: 구분자가 다르다. 쉼표 대신 세미콜론이나 탭일 수 있다. 또는 값 안에 쉼표가 들어 있다.

할 일: 파일을 메모장으로 열어 첫 두 줄을 확인한다. 무엇으로 나뉘어 있는지 눈으로 보고 알려 준다.

자료 올리기 전 점검

  • 첫 줄이 열 이름인가 (설명이나 제목이 위에 붙어 있지 않은가)
  • 중간에 요약 행이나 빈 행이 끼어 있지 않은가
  • 한 칸에 여러 정보가 들어 있지 않은가
  • 숫자에 쉼표나 단위가 붙어 있지 않은가
  • 같은 뜻인데 다르게 적힌 값이 있지 않은가
  • 병합된 칸이 없는가 (엑셀에서 만든 경우)

배포했는데 안 열린다

표 C.3: 배포 후 문제
증상 확인
404가 나온다몇 분 기다린다. 공개 설정을 켰는가. 파일 이름이 index.html인가
빈 화면확장자가 .html인가. 대소문자가 맞는가
옛날 것이 보인다강제 새로고침. 그래도 안 되면 다시 올렸는지 확인
휴대전화에서만 안 됨주소를 정확히 옮겼는가. 학교 와이파이를 끄고 시도
글자가 깨진다파일을 UTF-8로 저장
주의

올리자마자 안 열리는 것은 정상이다. 반영에 몇 분이 걸린다. 그 사이에 설정을 이것저것 바꾸다 더 망가뜨리는 일이 많다. 5분은 기다려 보자.

에이전트가 엉뚱한 것을 만든다

표 C.4: 지시대로 안 될 때
원인 할 일
지시가 모호했다다섯 요소로 다시 쓴다 (7.1절)
컨텍스트가 밀려났다결정 목록을 다시 준다 (2.4절)
한 번에 너무 많이 시켰다하나씩 나눈다 (7.3절)
앞의 결정과 어긋나는 요청무엇이 바뀌었는지 명시한다
요청하지 않은 기능이 붙는다넣지 말 것 목록을 명시
앞에서 고친 게 되돌아온다최신본을 다시 붙인다

새 대화를 시작해야 할 때

다음 중 둘 이상에 해당하면 새로 시작하는 편이 빠르다.

  • 같은 것을 세 번 넘게 고쳐 달라고 했다
  • 고칠 때마다 다른 곳이 망가진다
  • 대화가 아주 길어졌다
  • 주제가 바뀌었다

옮길 때는 빈손으로 가지 말고 2.4절의 요약 프롬프트를 쓴다.

그래도 안 될 때

되던 상태로 돌아간다

사본이 있다면 그것부터 연다. 되는 것을 확인한 뒤, 그 상태에서 한 번에 하나씩 다시 붙인다. 어느 단계에서 깨지는지 알게 된다.

더 작게 쪼갠다

기능 하나가 계속 안 되면, 그 기능을 반으로 나눈다. 예를 들어 파일을 읽어 정리해 내보내기가 안 되면 파일을 읽어 행 수만 출력부터 한다.

다른 도구에 물어본다

같은 파일과 같은 질문을 다른 서비스에 넣는다. 도구마다 잘하는 것이 다르고, 놓치는 것도 다르다.

처음부터 다시 만드는 편이 빠를 때도 있다

정직하게 말해 두자. 여러 번 고치다 엉킨 것은 되살리기보다 명세서를 들고 처음부터 다시 만드는 편이 빠를 때가 있다. 이것은 실패가 아니다. 6.5절의 명세서가 있으면 다시 만드는 데 30분이면 된다 — 명세서를 써 둔 값이 여기서 나온다.

사람에게 묻는다

8.5절의 네 가지를 적어서 간다. 적는 과정에서 스스로 답을 찾는 경우도 많다.

요점

막히는 것은 실력 문제가 아니라 경험의 문제다. 이 부록에 있는 것들은 누구나 처음에 겪고, 두세 번 겪으면 안 겪는다. 겪을 때마다 오류기록.txt에 적어 두면 그 과정이 빨라진다.
